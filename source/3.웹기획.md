**아우렐리스 MVP 웹 구조 및 기능 기획**

단일 스크롤 랜딩페이지와 Google Sheets 문의 저장 구조

기획 문서  |  2026.10  |  웹사이트 구축을 위한 기준안

본 MVP는 로그인·회원가입·결제·관리자 페이지 없이 운영한다. 방문자는 한 페이지에서 브랜드와 4개 제품 라인을 이해하고 문의를 남긴다. 문의 데이터는 Supabase가 아닌 Google Apps Script Web App을 통해 Google Sheets에 저장하며, 운영자는 Sheets에서 직접 확인한다.

**1 단일 스크롤 페이지 구조**

|           |                                     |                           |
| --------- | ----------------------------------- | ------------------------- |
| **앵커**    | **화면 구성**                           | **사용자 행동**                |
| #top      | 로고, 간결한 메뉴 앵커, 히어로, 대표 CTA          | 브랜드 첫인상 확인 → 제품 또는 문의로 이동 |
| #story    | 브랜드 한 문장, 가치 3개, 무드 이미지             | 왜 이 브랜드인지 빠르게 이해          |
| #products | 4개 제품 카드: 이름, 용량, 한 줄 메시지, 간단 사용 순서 | 제품을 비교하고 관심 제품을 선택        |
| #ritual   | 사용 감각·제형·루틴 소개                      | 제품의 사용 장면을 상상             |
| #contact  | 문의 유형, 기본 정보, 메시지, 동의, 제출           | B2B·제품·협업 문의 전환           |
| footer    | 회사 고지, 개인정보 처리방침 링크, 연락 수단          | 신뢰 정보 확인                  |



**핵심 UX** 상단 메뉴는 페이지 내 앵커 이동만 제공한다. 제품별 상세 페이지는 MVP에서 만들지 않으며, 제품 카드의 “문의하기”를 누르면 문의 폼으로 스크롤되고 관심 제품명이 자동 선택된다.

**2 최소 제품 데이터**

|               |                                  |            |
| ------------- | -------------------------------- | ---------- |
| **필드**        | **예시**                           | **사용 위치**  |
| slug          | lumen-hydra                      | 제품 카드 식별   |
| name          | 루멘 하이드라 글래스 에센스                  | 카드·문의 선택값  |
| volume        | 50 mL                            | 제품 카드      |
| message       | 맑은 결은 수분의 균형에서 시작됩니다             | 제품 카드      |
| benefits      | 보습·윤기·결 정돈                       | 짧은 보조 정보   |
| image         | /images/product-lumen-front.webp | 제품 팩샷      |
| inquiry_label | 루멘 하이드라 제품 문의                    | 문의 폼 자동 선택 |



**운영 원칙** 제품 데이터는 초기에는 코드 또는 정적 JSON 파일로 관리한다. 제품 수가 늘거나 편집 빈도가 높아질 때에만 CMS를 검토한다.

**3 문의 폼과 Google Sheets 흐름**

|                        |                                                                |
| ---------------------- | -------------------------------------------------------------- |
| **단계**                 | **처리**                                                         |
| 1. 사용자                 | 문의 유형·이름·이메일·문의 내용·개인정보 동의를 입력한다.                              |
| 2. 랜딩페이지               | 필수값과 이메일 형식을 검사하고 제출 버튼을 잠근 뒤 HTTPS POST를 전송한다.                |
| 3. Apps Script Web App | doPost에서 서버 측 검증, honeypot 확인, 길이 제한 후 Google Sheets에 행을 추가한다. |
| 4. Google Sheets       | inquiries 시트에 NEW 상태로 저장한다. 운영자는 필터뷰에서 확인하고 상태·메모를 갱신한다.       |
| 5. 완료 화면               | 접수 완료와 일반적인 회신 안내를 표시한다. 개인정보는 화면에 다시 노출하지 않는다.                |



**4 inquiries 시트 필드**

|                  |        |                                              |
| ---------------- | ------ | -------------------------------------------- |
| **열**            | **필수** | **설명**                                       |
| created_at       | 자동     | Apps Script가 기록한 접수 시각                       |
| inquiry_id       | 자동     | UUID 또는 짧은 접수 식별자                            |
| type             | 필수     | 제품 / 도매 / 협업 / 기타                            |
| product_interest | 선택     | 제품 카드에서 넘어온 관심 제품                            |
| name             | 필수     | 2–60자                                        |
| email            | 필수     | 회신 이메일                                       |
| phone·company    | 선택     | 필요할 때만 수집                                    |
| message          | 필수     | 10–2,000자                                    |
| privacy_consent  | 필수     | 개인정보 처리 동의 true                              |
| source_page      | 자동     | 제출 화면 경로                                     |
| status·memo      | 운영     | NEW / IN_PROGRESS / REPLIED / CLOSED 및 내부 메모 |



**5 검증, 보안, 개인정보**

클라이언트와 Apps Script에서 모두 필수값, 이메일 형식, 글자 수, 개인정보 동의를 검증한다. HTML 태그와 제어문자는 저장 전에 제거 또는 무력화한다.

봇 방지는 숨김 honeypot, 최소 작성 시간, 동일 요청의 짧은 시간 내 반복 제한으로 시작한다. 악성 유입이 지속될 때 CAPTCHA를 추가한다.

Apps Script와 Sheets는 운영 담당자에게만 편집 권한을 준다. 시트 공개 링크를 사용하지 않고, 로그에 원문 개인정보를 남기지 않는다.

개인정보 처리방침에 수집 목적·항목·보유 기간·파기 절차·동의 거부 권리를 고지한다. 최종 문구와 보유 기간은 적용 법령에 맞게 검토한다.
